Oath

A Linux distribution: the Linux kernel and its own userspace, PID 1 included. The machine is a catalog of typed objects at /oath, and one command, oath, reads and changes it. People and AI agents use it the same way, and every change can be undone.

Goals

An AI agent can run the machine. A new operating system has no forum answers and no training data, so the running machine has to explain itself. /oath/INDEX.md is generated from the live catalog: the verbs, the kinds of object on this machine and the safety rules. An agent that has never seen Oath reads it, or connects with ssh -T home@host oath mcp and gets each verb as a tool. Its changes go through sudo and into the same log as the owner's. The acceptance test gives a model nothing but that server and a task.

One catalog, one command. Everything you administer is an object with a typed schema: host:local, svc:sshd, pkg:curl. oath set writes what you want, oath diff shows how it differs from what is applied, and oath apply makes it so. There are no files in /etc to edit and no unit files. Unix is the substrate, not the admin interface.

Every change can be undone. oath apply checks every object before it touches the machine, and a refusal changes nothing. Then it snapshots the root filesystem to a btrfs generation and converges. oath undo puts back what the last apply changed. A change that could cut off SSH goes on probation: PID 1 reverts it after 180 seconds unless it is kept from a new session.

Independent, and built from source. Oath is not a remix of Debian, Arch, NixOS, Alpine or Ubuntu. PID 1, the catalog, oath, the boot loader and the installer are written for Oath, in Rust. Every other package, the kernel, GCC and glibc among them, is built from pinned source by an Oath plan or is the vendor's own release pinned by sha256. No package comes from another distribution, and rebuilds are bit-identical.

Open to inspection. Every package is published at store.oath.moonlight.pm with its licence, the plan that built it and the source that plan pins, so the origin alone can rebuild any of them. Sources are checked against their upstream signatures where upstream signs.

Small on purpose. One compiler, one C library, one GNU tool for each job. Two accounts, root and home, and no /usr. The machine belongs to one person.

The catalog

A machine is a set of objects. Each has an id, kind:name, a desired state that you write and an actual state that the machine reports. There are eight kinds. The counts are from one machine on 26 October 2026: a 2013 Mac Pro that runs Oath as a desktop.

What works today

PID 1
Runs only applied svc specs, each in its own cgroup with its own log. Restarts a failing service with backoff, then marks it failed with a reason. Restarts a service when an apply moves the package its program comes from. Stops services in reverse order at shutdown, loads kernel modules by modalias, and survives its own panic.
oath
ls schema get set new rm diff apply keep undo verify log logs fmt build store mcp, each with --json. A failure names the next step to take.
Agents
oath mcp over SSH: one tool per verb, the INDEX as instructions, --read-only for an agent that only looks. The apply log records which agent made each change.
Generations
A btrfs snapshot before every apply. oath undo repeats to go further back. The boot menu keeps the last five boots.
Packages
A store addressed by hash, /bin and /lib link farms, a needs graph, origins tried in order, oath store for a tree built on the machine, and oath verify at every boot. A package whose licence forbids redistribution ships as a recipe that the machine builds itself.
Plans
Builds in a sandbox with no network and its own PID namespace, cached by plan and inputs. Everything in the image is a plan product: the kernel, the toolchain and Oath's own binaries.
Toolchain
GCC, binutils and glibc built from source, bootstrapped once by the build host and then rebuilt by themselves. bash and the GNU userland; zsh is the login shell.
Kernel and boot
Linux from kernel.org, pinned by sha256 and built as a plan. oath-efi is the only boot loader, and the initrd runs Oath's PID 1.
Network and SSH
net0 by DHCP or a static address, time from pool.ntp.org, OpenSSH for SSH as home with root login refused, the network daemons dropped to the unprivileged void, and dig.
Install
cargo make install over SSH to a named disk, or to a USB stick; from a stick booted on the machine, oath install lists the disks and copies the system onto the one you name, with home in its own subvolume. Each machine updates itself: oath update takes the newest output its build host signed, without wiping it.
Testing
cargo make check boots one QEMU machine per case and reboots for real. --target runs the hardware cases on an installed machine and undoes each one. --agent gives a real model five administration tasks.
Desk
Optional: a desktop. rivulet, a C port of the River compositor on wlroots, runs the shell, terminal, Projects, browser and Design of Sola, with Mesa's RADV for Vulkan and PipeWire for sound.

The manual covers each of these in detail.

Status

Oath is pre-alpha and not a daily driver. There are no releases or install images to download: you build it from source and install it over SSH, or from an Oath stick with oath install. As of 30 October 2026 the current build passes all 63 test cases in QEMU, and oath install its rehearsal; the desk's hardware cases passed on the Mac Pro on 22 October, and the hardware cases that apply to a headless Intel machine on 27 October; on 30 October oath install put it on an AMD desktop with an NVIDIA card, from a stick. Not there yet:

  • Releases. x86-64 with UEFI is the only platform.
  • A signed package index. Packages are pinned by hash, their sources are checked against upstream signatures, and machines update only to builds their build host signed, but the index of the pack origin is not signed.
  • More than one network interface. One is chosen at boot.
  • Device node ownership as a catalog field.
  • Desktop applications beyond Sola's terminal, Projects, browser and Design, and Steam: its 64-bit client runs on the Mac Pro with 32-bit Mesa built from source, but gamepads do not yet.

The work under way is in CURRENT.md, the decisions behind it in docs/decisions.md, and what each part can do in docs/capabilities.md.

Building

You need an x86-64 Linux build host with Rust, Nix (for the stage-0 compilers and QEMU), sudo and mkfs.btrfs. The first toolchain build takes an hour or more.

git clone https://github.com/moonlight-pm/oath
cd oath
cargo make bootstrap    # the toolchain, once
cargo make pkgs         # every package in pkgs/, from source
cargo make build        # the base image
cargo make check        # the QEMU test cases
cargo make run          # boot it, with the serial console in this terminal

Installing wipes the target disk: from the build host over SSH, or with oath install from an Oath stick booted on the machine; the manual has the steps.
