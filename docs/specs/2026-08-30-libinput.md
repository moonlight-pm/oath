# Libinput without udev

River already holds DRM. This freeze is pointer and keyboard on that
compositor. **Not** udevd. **Not** `pkg:libinput`. **Not** a new kind.

T19 already puts virtio keyboard and mouse on the QEMU appliance.
devtmpfs exposes `/dev/input/event*` once the **evdev** module is
loaded. libinput is linked into `pkg:river`. Without udevd, systemd
libudev leaves those nodes uninitialized and wlroots’ udev backend
finds nothing.

---

## Locks this freeze owns

- **No udevd.** Not systemd-udevd, not eudev, not mdev pretending to
  be udev. T17 still holds: the agent does not run `udevadm`.
- **libinput is borrowed** inside `pkg:river` (already packed). It is
  not a fork and not its own `pkg:*`. Something on the box does not
  exec `libinput` as a binary. **libudev** in that tree is
  **libudev-zero** (borrowed), not systemd-udevd.
- **River sees `/dev/input/event*`.** Patch `forks/wlroots`: if the
  udev backend adds no devices, fall back to libinput’s **path**
  backend and add every `/dev/input/event*`. No hotplug in v0.
- **evdev** is a hardcoded initramfs module, same list as virtio-gpu.
- Catalog: **`dev:kbd0`** and **`dev:mouse0`**, `class=input`, not
  removable. Converge probes `/sys/class/input/event*/device/name`
  (keyboard vs mouse/pointer). Nodes are not stable event numbers.
- Drop `WLR_LIBINPUT_NO_DEVICES` from the River wrapper.
- Probe stays headless. gtk with `DISPLAY` is how a human moves the
  pointer; probe does not require a host display.

---

## Courage test

On the QEMU appliance (probe headless is enough for 1–5):

1. `test -c /dev/input/event0` (evdev nodes exist).
2. `oath get dev:kbd0 --actual` · `oath get dev:mouse0 --actual` —
   `present` true, `class` `input`, `node` `/dev/input/event*`.
3. `svc:river` still stable; Wayland socket still up.
4. `/oath/log/river.log` shows both devices added.
5. Serial and SSH still work. Probe still passes.
6. With `DISPLAY`, the gtk window takes pointer and keyboard (not
   probed).
