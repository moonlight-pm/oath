# Sola / app development on Oath (layout)

When Oath is the machine you develop on, a development version is a
**package generation of the real object** — not a shadow prefix, not a
second PATH, not a nested Sola process manager.

Until Oath is that host, **develop Sola on NixOS.** Re-address this
freeze then. T20 (`pkg.url`) stays the fetch identity.

---

## Locks this freeze owns

- **The catalog object is the install.** Bits live in
  `/oath/store/pkg/<name>/`. `/bin` is the symlink farm (T11). How you
  run it is `/bin/<file>`, never a raw store path, never `/opt/sola`
  on Oath.
- **Replace** is `oath apply` on that object (store already filled, or
  `pkg.url` filled it). **Test with a way back** is the same apply:
  snapshot first; `oath undo` restores the previous store tree and
  reconverges `/bin`. Live `@` takes precedence; `@gen-N` is the
  previous payload. That is the test area.
- **Two versions runnable at once** is two names (`pkg:foo` and
  `pkg:foo-wip`). Same kind. Do not point `svc.exec` at the store to
  hide a second binary.
- **Keep one `pkg:sola` blob** (libs, share, and the session ELFs).
  Split per `/bin` name only when we re-address. First-party
  apps we write stay `apps/` → `pkg:<name>`.
- **Develop Sola on Nix** (`cargo make install`, `/opt/sola`,
  `crates/sola` as PM) until Oath is the host system. The appliance
  is packed from that work (`forks/sola` + `cargo make build`).
- **`oath-sola` is dual-mode.** Detect the seat at runtime (`/oath`
  vs `/opt/sola`). One tree, one set of binaries. Do not land Oath
  catalog types on NixOS Sola. Do not grow `/opt/sola` on Oath.
- No `pkg:sola-dev`. No `/oath/store/dev`. No extra PATH. No 9p /
  virtiofs as the architecture (QEMU convenience only, if ever).
- No new verbs. Git is not the live store (T20). PID 1 stays the
  only supervisor (T21/T23).

When this is re-addressed (Oath as host): install is still apply;
reload is self-watch on the ELF (same pid) and/or signal +
`restart=on-failure` for processes that do not self-watch. PID 1
does not become a file watcher.
