# Vendor-updating packages (`pkg:grok`)

Grok Build (`grok`) is a borrowed static-pie ELF that, off Oath,
installs under `$GROK_HOME` and replaces itself (`grok update`,
`[cli] auto_update`). That is a second package manager. Oath does not
run it.

This freeze is the identity of that class of payload. It does not pack
the ELF or grow `pkg:sola`. Extends T11/T20/T24. T31 (seat + catalog
env) is the enforcement slice and is in.

---

## Locks this freeze owns

- **`pkg:grok` is the install.** Bits live in
  `/oath/store/pkg/grok/`. `/bin/grok` is the symlink farm (T11). Do
  not add `pkg:grok` to the Sola blob. Do not run `install.sh` on the
  guest. Do not put `~/.grok/bin` on PATH.
- **Grok does not update Grok.** The updater is off. A newer build
  lands the same way any package does: fill the store, `oath apply`.
  `grok update --check` (and launch telling the operator) is how we
  **learn** a version exists. Apply is how we **change** the bits.
  Explicit `grok update` that writes a new ELF is out of policy even
  when the process is root.
- **`$GROK_HOME` is user state**, not the payload. Auth, sessions,
  config, skills, memory stay there (`/home/.grok`). The ELF is not
  in that tree.
- **Borrowed prebuilt.** The Linux x86_64 binary is static-pie; it
  does not need `pkg:glibc`. Pack it like other host-borrowed
  payloads. First-party sources stay under `apps/`.
- **No new kind. No new verbs.** Removable. `pkg.url` may point at an
  x.ai artifact later; local store still wins if the file is already
  there (T18/T20). Refetch-when-url-changes is not this freeze.
- **`pkg:git` is the same store shape** (borrowed, not
  vendor-updating). Not packed in this freeze.

T29’s “borrowed prebuilts or helpers in the blob” is the later land,
not a lock that Grok lives inside `pkg:sola`.
