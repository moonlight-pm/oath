# Plan kind — replicate a build

Amends [2026-09-03-pkg-pack-identity.md](2026-09-03-pkg-pack-identity.md)
(no recipe *language*; a hashed plan **file** is allowed),
[2026-08-30-pkg-hosting.md](2026-08-30-pkg-hosting.md) (T20 fetch is
pre-build, not in-sandbox),
[2026-09-13-pkg-needs.md](2026-09-13-pkg-needs.md) (`run_needs` → product
`needs`). Same catalog. New kind. New verbs `oath build` and `oath fmt`.

People **install by reproducing a build**: same plan bytes + same input
pack hashes → same product tree hash. `/bin` still waits on `oath set`
+ `oath apply`.

---

## Locks this freeze owns

- **Kind `plan`.** Catalog id `plan:<name>`. Name is a slot; hash is
  the bits (same rule as `pkg`). Store
  `/oath/store/plan/<name>/<hash>/plan.plan`. Realization id is
  `sha256-` plus 64 lowercase hex of **SHA-256 of that file’s bytes**
  (not `oath-tree-v1`; plans are one file). Directory contains only
  `plan.plan`.
- **One plan → one product.** `name` in the file, the slot
  `plan:<name>`, and `produces: "pkg:<name>"` are the same `<name>`.
  Mismatch refuses. No multi-output plans.
- **No anonymous blobs.** Every hashed input is a named catalog
  object (`pkg:*` at a pin). Source tarballs are a pkg (e.g.
  `pkg:hello-src`) with `url` + `hash` (T20). There is no
  `/oath/store/blob`. Pre-build **fetches missing `build_needs`**
  that have `url`, verifies the hash, **then** the sandbox starts.
- **`oath build plan:<name>`** uses `desired.hash` (the pin). Refuses
  if unpinned. Does **not** set `pkg` present or link `/bin`.
- **Ad-hoc / tidy:** `oath build --file ./hello.plan` lints and
  builds **without** copying into `/oath/store/plan/`. Product still
  lands at `/oath/store/pkg/<name>/<product-hash>/`. Filing is
  explicit: `oath set plan:<name> --from-file ./hello.plan` (lints,
  stores, pins). Iterate with `--file`; locate when you mean it.
- **Canonical file (lint is a gate).** `oath fmt <path>` writes the
  only legal form. `build` / `--from-file` refuse unless the bytes
  are already that form (no silent rewrite before hash). Format
  below.
- **Two dep lists.** `build_needs`: sandbox PATH/store only.
  `run_needs`: copied onto the product as `pkg.needs` after a
  successful build. Both are `{id, hash}` (T41).
- **Enforce isolation.** New mount + net namespaces (and pid/ipc as
  needed). **Network off** in the sandbox. No `/home`. Only declared
  `build_needs` packs at those hashes (and a scratch `/out`).
  Undeclared `/bin/cc` does not exist. Engine is an implementation
  detail; the lock is this isolation, not bwrap-as-ontology.
- **`built_from` is not a proof.** Optional actual field on the
  product for humans/agents. **Security is hashes:** plan file,
  each `build_needs` pin, each fetched pkg tree, product tree.
  Rebuild of the same pins that yields a **different** product hash
  is a **security error**: do not record success, do not change the
  live pin, keep both trees, hint the plan is not closed.
- **Build as `home`.** The script is not root. Oath (root) hashes
  `/out` and writes the store after the sandbox exits.
- **Idempotent:** product tree already in the store → skip compile.
  Same `(plan hash, input-set hash)` already recorded → reuse that
  product. Input-set hash is the sorted `build_needs` id+hash list.
- **No new kind besides `plan`.** No `src` kind. No recipe DSL.

## Plan file (canonical)

One UTF-8 file, no BOM, newline at EOF. Exact skeleton:

```
#!oath-plan
{
  "name": "hello",
  "produces": "pkg:hello",
  "build_needs": [
    {"id": "pkg:busybox", "hash": "sha256-<64 hex>"},
    {"id": "pkg:cc", "hash": "sha256-<64 hex>"}
  ],
  "run_needs": [
    {"id": "pkg:glibc", "hash": "sha256-<64 hex>"}
  ]
}
---
#!/bin/sh
set -eu
```

Locks on the JSON object:

- Pretty-print, **2-space** indent, no trailing commas.
- Key order **only:** `name`, `produces`, `build_needs`, `run_needs`.
  No other keys.
- `build_needs` and `run_needs` sorted by `id` lexicographically.
- `id` is `pkg:<name>` (or `pkg:`-less → normalize then refuse if
  it didn’t match canonical `pkg:…`).
- `hash` is `sha256-` + 64 lowercase hex.
- After `---`, exactly `#!/bin/sh` then `set -eu` as the first two
  script lines. POSIX `sh` only (busybox from a declared
  `build_needs`).

`oath fmt` emits this. Hash is SHA-256 of the **whole file**.

## `oath build`

1. Lint the plan (pin or `--file`).
2. **Pre-build:** every `build_needs` pack present at that hash; if
   missing and `url` is set, T20 fetch + verify; else refuse. Network
   may be used **only** in this step.
3. Sandbox: net down; only those packs; `/out` empty; run the script
   as `home`. Script may re-hash inputs; that is not the root of
   trust (the mount is).
4. Tree-hash `/out` (`oath-tree-v1`, T32). Write
   `/oath/store/pkg/<name>/<product>/`. Do not `present=true`.
5. If a previous successful record for this `(plan, inputs)` exists
   and the new product hash **differs** → security error (above).

`oath build --file` skips step filing the plan. It still requires
the `build_needs` pkgs.

## Courage test (v0)

**First:** a relocate plan (T35-shaped): hashed upstream tar as
`pkg:<name>-src` (`url`+`hash`), `build.sh` unpacks/relocates into
`/out`. `oath build --file`, then `oath set plan:<name> --from-file`,
then `oath build plan:<name>` → same product hash. Second apply of
build is a no-op. `/bin` still absent until pkg apply.

**Then:** `apps/hello` compiled with declared `pkg:cc` (and busybox).
A plan that calls `cc` **without** `pkg:cc` in `build_needs` fails
in the sandbox.
