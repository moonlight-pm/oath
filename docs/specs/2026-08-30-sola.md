# Sola on Oath (River first)

Sola is the graphical session. Oath is the OS. This freeze is the
first slice toward running that session on this kernel and PID 1 —
**not** a throwaway compositor, **not** a placeholder `pkg:sola`,
**not** Sola’s NixOS module copied in.

Sola today is a NixOS daily driver: River (patched via nixpkgs
overlay), `sola` as a process manager, bus/call/shell/session as
children. Oath already has a supervisor. Do not nest one.

---

## Locks this freeze owns

- **First courage is patched River**, the compositor Sola actually
  uses. Objects: **`pkg:river`** (bits) and **`svc:river`** (PID 1
  starts it). Talks to `dev:card0`. Serial stays.
- **PID 1 remains the only supervisor.** Do not run Sola’s process
  manager (`crates/sola`) as a second init. Later Sola components
  are `svc:*` that `wants` `svc:river` (and each other). The Sola
  fork exists to make that mapping, not to preserve a nested
  supervisor.
- **glibc is a runtime object** for this payload (D2). River/Sola
  may be glibc-linked. Oath PID 1, `oath`, and the musl base do not
  load glibc. v0: sealed **`pkg:glibc`** — loader and libs under
  `/oath/store/pkg/glibc/`. Never two libcs in one process.
- **Build-time forks** live in this repo under **`forks/`** as git
  submodules of trees we maintain. That is not the live package
  store (T20). Apply still does not clone.
- **Fork River and wlroots**, not a nixpkgs overlay. Sola’s carried
  patches (`nix/patches/` in the Sola tree: three River, one
  wlroots) become commits on those forks. A patch-file overlay is
  not an Oath package dialect.
- **Fork Sola** for Oath-compat work. The NixOS daily-driver tree
  stays the daily driver. Do not land Oath PID 1 / catalog / musl
  assumptions on that main.
- **`forks/` is only product forks** (we patch or we reshape).
  Unmodified borrowed prebuilts stay in `image/` (D8). First-party
  programs we wrote ship from **`apps/`** (`hello`, `fetchme`, later
  canaries) and pack into `pkg:*`. They are not submodules.

## Courage test (this slice)

On the QEMU appliance, with `DISPLAY` so gtk can show the GPU:

1. `oath get pkg:glibc` actual present (sealed).
2. `oath get pkg:river` · `oath get svc:river` — river running.
3. A Wayland socket exists under `/run` (or `$XDG_RUNTIME_DIR`).
4. The gtk window is the compositor, not only the kernel fb
   console. Serial and SSH still work.
5. Probe stays headless and still passes (river may run on DRM
   without gtk; probe must not require a host display).
